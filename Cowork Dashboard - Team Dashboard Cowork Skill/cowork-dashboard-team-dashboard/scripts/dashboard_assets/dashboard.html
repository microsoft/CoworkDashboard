Glossary of terms

Active days — Person-days with at least one Cowork task in the window.

Anonymity — A role or attribute is shown separately only when at least __KTHRESH__ contributors share it; otherwise contributors are combined. Nothing is ever shown per person.

Business process — The business need served by the work — e.g., Business Value & ROI Analytics.

Contributors — The number of teammates who posted their de-identified stats this period. Never named.

Cowork fit — How well a task suited Cowork's agentic, cross-app strengths, graded High / Medium / Low. High = work only Cowork can do (builds & packaged skills, executed automations, many-source synthesis); Low = a single-app Copilot could have done it. Shown as a quantified waterfall on the How Cowork is used tab.

Deliverables — The count of distinct pieces of work produced.

Hands-on time — The actual time the team spent working with Cowork.

Outputs — Every output file and version created. May be higher than deliverables because it counts each file and version.

Reach — How many contributors used a given task category. Withheld as “<__KTHRESH__” when fewer than __KTHRESH__ share it.

Research time band — The low / typical / high minutes of manual time saved per run for a task category, drawn from published studies (see “” below).

Run tasks — A single unit of work run with Cowork — one discrete request or action (e.g., analyzing a file, drafting a document). Run tasks are grouped into sessions.

Sessions — Distinct Cowork chats run across the team. A session may contain one or multiple run tasks.

Skills — The specific capabilities behind roles (e.g., Data Visualization, Python).

Task category — How the work was done (the method) — e.g., Analysis & Research, Write or debug code. Each carries a research time band (see “” below).

Team speed multiplier — How much faster the work went: estimated hours without Cowork ÷ actual hands-on with Cowork hours.

Time saved — Manual hours Cowork saved this period: for each task, run tasks × the research time band for its category. The headline is the typical estimate, with a low–high range alongside.

Recapture rate — The share of time saved the team can realistically harvest into productive output. Set in the control bar (default __RECAP__%). It scales every value figure but leaves time-saved hours and counts unchanged.

Effective time recaptured — Time saved × the recapture rate — the productive hours the team actually reclaims. This is what the value figure prices.

Value / cost reduction — Effective time recaptured priced out: time saved × recapture rate × the hourly rate in the control bar. Recomputes whenever you change the rate or the recapture rate.

How task categories are derived

Each task is sorted into up to two categories from three signals:

1 · Output file type

  • spreadsheets (.xlsx / .csv / .json) → Analysis & Research
  • code & web (.py / .html / .sql / .js) → Write or debug code
  • documents (.docx / .pdf / .pptx / images) → Document & content creation
  • packaged skills (.zip / .skill) → Specialized workflows

2 · Goal keywords

  • “analyze / research / ROI / benchmark” → Analysis
  • “debug / refactor / script / API / automation” → Write or debug code
  • “email / inbox / reply” → Email
  • “meeting / transcript / standup / agenda” → Meeting

3 · Input signal

  • if the sources are data files, or there are 3 or more of them → Analysis

A task with no saved file and no signal falls to General assistance / Other. When more than one matches, they rank (code › analysis › specialized › document › communication › meeting › email › general) and the top two are kept.

Privacy & anonymity

Nothing is shown at an individual level. Members appear only as counts. The one per-attribute view (category mix) breaks a Role out only when __KTHRESH__+ contributors share it; otherwise they collapse into a single combined bar. The only attribute used is the directory Role (job title) that a teammate's post carries — never names, never country, never file names or prompts.

Value model
  • Time saved = Count of run tasks × the research band (minutes saved/run).
  • Recapture rate = the share of time saved the team realistically converts into productive output (default __RECAP__%; adjustable in the control bar).
  • Effective time recaptured = time saved × recapture rate.
  • Value / cost reduction = effective recaptured hours × hourly rate (default $__RATE__/hr) = time saved × recapture rate × rate.
  • Speed multiplier = manual hours ÷ modeled hands-on hours.

All figures come from the posts; the dashboard only re-totals and re-prices them.
